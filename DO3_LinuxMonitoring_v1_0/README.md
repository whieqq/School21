# DO3_LinuxMonitoring_v1_0 - bash-скриптинг и исследование системы

Учебный проект DevOps-трека Школы 21. Набор bash-скриптов: сбор информации о системе, цветной вывод с настройкой через параметры и конфигурационный файл, анализ файловой системы.

Сдан на максимальный балл (100%).

## Структура

```
src/01/main.sh            - обработка аргументов командной строки
src/02/main.sh            - сбор информации о системе с сохранением отчёта
src/03/main.sh            - цветной вывод, цвета задаются параметрами
src/04/main.sh            - цветной вывод, цвета читаются из файла
src/04/config.config      - конфигурация цветовой схемы
src/05/main.sh            - анализ содержимого каталога
```

## 01. Обработка аргументов

Принимает ровно один текстовый параметр и возвращает разные коды выхода на разные ошибки: параметр не передан, передано больше одного, передано число вместо текста.

```bash
./main.sh привет     # выводит параметр
./main.sh            # код 1: параметр не введён
./main.sh a b        # код 2: недопустимое число параметров
./main.sh 42         # код 3: введено число
```

Число распознаётся регулярным выражением, с учётом знака и дробной части.

## 02. Сбор информации о системе

Собирает и выводит состояние машины:

```
HOSTNAME, TIMEZONE (с указанием смещения UTC), USER, OS, DATE, UPTIME,
UPTIME_SEC, IP, MASK, GATEWAY,
RAM_TOTAL / RAM_USED / RAM_FREE (в GB, 3 знака после запятой),
SPACE_ROOT / SPACE_ROOT_USED / SPACE_ROOT_FREE (в MB, 2 знака)
```

После вывода предлагает сохранить отчёт в файл. Имя файла формируется по шаблону `DD_MM_YY_HH_MM_SS.status`.

Что интересного внутри:

- **IP, шлюз и интерфейс** берутся одним запросом `ip r get 8.8.8.8` - ядро само выбирает маршрут до внешнего адреса и возвращает `src`, `via` и `dev`. Это надёжнее, чем перебирать интерфейсы.
- **Маска** приходит в CIDR-записи, поэтому в скрипте есть перевод префикса в десятичные октеты - цикл по четырём октетам с вычислением `256 - 2^(8-n)` для неполного октета.
- **Единицы измерения** - десятичные: GB и MB считаются как степени 1000, а не 1024, в соответствии с условием.

## 03. Цветной вывод через параметры

То же, что и 02, но без сохранения в файл и с раскраской. Принимает четыре параметра, каждый от 1 до 6:

```bash
./main.sh 2 4 5 1
```

1. фон названий
2. цвет шрифта названий
3. фон значений
4. цвет шрифта значений

Цвета: `1 - white`, `2 - red`, `3 - green`, `4 - blue`, `5 - purple`, `6 - black`.

Проверки: количество параметров, диапазон каждого значения и совпадение фона со шрифтом внутри одной колонки - в последнем случае текст стал бы нечитаемым, поэтому скрипт завершается с ошибкой. На любую ошибку печатается справка по параметрам.

Раскраска собрана на ANSI-кодах через две ассоциативные таблицы: номер цвета -> код шрифта и номер цвета -> код фона.

## 04. Цветной вывод через конфигурационный файл

Та же программа, но параметры командной строки заменены файлом `config.config`:

```
column1_background=2
column1_font_color=4
column2_background=5
column2_font_color=1
```

Файл разбирается построчно, значения вне диапазона 1-6 и пустые строки игнорируются - для них подставляется цвет по умолчанию. После информации о системе скрипт печатает использованную цветовую схему с указанием, какие значения взяты из файла, а какие остались умолчаниями.

Файл в репозитории заполнен частично - это рабочий пример: показывает, что скрипт корректно отрабатывает незаданные параметры.

## 05. Анализ файловой системы

Принимает один параметр - путь к каталогу, обязательно со слешем на конце. Проверяет формат пути и существование каталога.

```bash
./main.sh /var/log/
```

Выводит:

- общее число папок, включая вложенные
- топ-5 папок по размеру
- общее число файлов
- количество файлов по типам: конфигурационные (`.conf`), текстовые, исполняемые, логи (`.log`), архивы, символические ссылки
- топ-10 файлов по размеру, с путём, размером и типом
- топ-10 исполняемых файлов по размеру, с путём, размером и MD5-хешем
- время работы самого скрипта

Что интересного внутри:

- **Тип файла определяется содержимым, а не расширением** - через `file --mime-type`. Текстовые ищутся по `text/`, архивы - по списку mime-типов (`zip`, `gzip`, `x-tar`, `x-xz`, `x-bzip2`, `x-rar`, `x-7z-compressed`).
- **Размеры приводятся к человекочитаемому виду** функцией на awk, с последовательным делением на 1000.
- **Сортировка по размеру** сделана через `find -printf "%s\t%p\n"` с разделителем-табуляцией, чтобы пробелы в именах файлов не ломали разбор.
- **Время работы** замеряется с точностью до долей секунды через `date +%s.%N` и `bc`.

## Стек

bash, find, awk, sed, grep, du, df, file, md5sum, iproute2, ANSI escape-коды

## Результат

Основной навык проекта - писать скрипты, которые не падают от неожиданного ввода: проверяют аргументы, возвращают осмысленные коды выхода и разбирают вывод системных утилит текстом, а не глазами.
